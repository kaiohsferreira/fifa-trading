Bugs detalhados para QA

QA-FE-002 | Alta | Aberto

Area/tela: Login / bootstrap inicial
Pre-condicoes: frontend local disponivel e backend homologado confirmado
Massa: sem dependencia de login para reproduzir

  • Passos para reproduzir: abrir / e observar console e network no carregamento inicial.
  • Resultado esperado: a tela de login deve carregar sem erro fatal de console.
  • Resultado obtido: houve duas falhas 500 em GET /Menu/GetMenus?token=ASIDE.
  • Sintoma: erro de console durante o bootstrap do frontend.
  • Evidencia tecnica: screenshot 01-login-desktop.png e JSON tecnico da rodada.
  • Impacto para a pessoa usuaria: o sistema pode iniciar com menu quebrado ou comportamento instavel antes da autenticacao.
  • Hipotese de causa provavel: dependencia de menu lateral indisponivel ou endpoint backend com erro interno.
  • Proxima acao recomendada: analisar logs do backend e validar o contrato/parametro `ASIDE` no endpoint de menu.
QA-AUTH-001 | Alta | Aberto

Area/tela: Autenticacao
Pre-condicoes: credencial de teste carregada na engine de QA
Massa: usuario de teste configurado; senha omitida

  • Passos para reproduzir: abrir /, preencher credenciais de QA e clicar em Entrar.
  • Resultado esperado: a autenticacao deve retornar sucesso e criar sessao/token.
  • Resultado obtido: POST /Account/Login respondeu 401 e nao houve sessao na aplicacao.
  • Sintoma: a URL permaneceu em / e o smoke autenticado foi bloqueado.
  • Evidencia tecnica: screenshot 05-post-login.png, JSON tecnico e resposta HTTP 401.
  • Impacto para a pessoa usuaria: a pessoa usuaria de teste nao consegue entrar no sistema e as rotas internas ficam sem validacao.
  • Hipotese de causa provavel: credencial de QA invalida, expiracao do usuario de teste ou regra de autenticacao alterada.
  • Proxima acao recomendada: validar a conta de teste e repetir o smoke apos restaurar login bem-sucedido.
